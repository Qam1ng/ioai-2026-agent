Code competition 的 kernel，分数为 0 的原因通常不是模型差，而是文件没落地。三条经实测有效的做法：

1. **三级写盘，越早越好**。读完 sample submission 立刻写全零占位（早于解码、特征提取、from_pretrained）；拿到最便宜的可用模型（如冻结特征线性探针）立刻覆盖成真实提交；之后每训完一个集成成员再覆盖一次。任何一级崩掉，上一级的文件都还在。占位要早于解码——把占位写在解码后是常见疏忽，而解码/特征提取恰恰是最容易因环境差异崩掉的一段。

2. **兜底分支必须强制触发验证，语法通过的兜底经常是死代码**。OOM 降级路径用 `torch.cuda.set_per_process_memory_fraction` 把显存压到低于实测峰值来触发真实 `OutOfMemoryError`；依赖安装兜底用一个不存在的搜索根目录触发 `FileNotFoundError`。注意别写死 fraction 比例——同一台机器不同卡的显存可能差一倍，要按绝对 GiB 反算。

3. **先量显存再决定要不要开 gradient checkpointing**。它掉 20~40% 吞吐，而吞吐在有时限的 kernel 里直接换成集成成员数。测出峰值远低于卡容量就别开，只放在 OOM 后的重试路径里。

配套：训练循环用墙钟守卫（读环境变量的预算），并且只在"1.15 × 上一个成员耗时 + 余量"仍放得下时才启动下一个成员，慢机器上退化成更少成员而不是被硬杀。
