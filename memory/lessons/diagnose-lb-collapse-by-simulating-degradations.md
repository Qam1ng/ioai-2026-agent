当 kernel 的公榜分远低于本地（尤其低于朴素保底），不要靠猜「id 错位 / 训练截断 / 分布漂移」——**在本地解码器上把每种退化形态模拟一遍，算出它各自对应的分数，再与实测分对号入座**。这能把一个模糊的事故变成一个唯一解。

实例（IOAI task-5，句边界 changepoint）：sibling 本地 96.48 → 公榜 41.52。模拟三种退化：
- NaN log-odds（`s > best` 恒假 → 锁死窗口第一个候选）→ 2.23
- 窗口内均匀随机 → 11.11
- **未训练 head（log-odds sd≈0.05），位置先验独自决定 → 40.43** ← 与 41.52 重合

结论唯一：分类器 log-odds 幅度塌到 0，预测完全由先验产生。id 错位和 fp16 溢出都被排除，两者差一个数量级。

由此推出的两条通用防护：
1. **准入门禁**：多段递进的 kernel 里，后一段只有通过健全性检查才允许覆盖前一段的产物。阈值必须用**真实 OOF 中间量**标定（本例 log-odds sd=6.29 / pos_rate=0.357），并刻意放松——只拒绝坏掉的模型，不拒绝平庸的模型。
2. **「赢过保底」不是分类器有输出的证据**。若保底本身很低（39.42），塌缩后的模型（~40）照样能险胜放行。闸门要查**边际幅度**和**中间量的分布**（sd、正例率、有限性），不能只查最终分数排序。

**Why:** 本地分数与榜单分数之间只有 kernel 这一个黑盒；模拟退化是把黑盒的失败模式变成可枚举、可对号的少数几个数。
**How to apply:** 任何「本地好 / 线上崩」的事故，先花 2 分钟在已有 OOF 中间量上模拟 3~4 种退化并打分，再决定查哪里。同时给多段 kernel 加基于中间量分布的准入门禁，而不是只加 try/except。
