任务型：给定一段文本，预测人写部分结束/机器续写开始的字符下标（metric = 100*mean(exp(-|d|/100))）。

1. 先做候选集压缩。检查真值落点的字符上下文：本题 boundary 100% 落在句子起点。把连续回归问题变成「约 20 个候选点上的分类」，官方 baseline 28.6 → 93+。任何 seq-labeling/回归 baseline 都不该先写。

2. 主结构：句级探针 + 累积对数似然变点解码。
   score(k) = Σ_{i<k} log P(human|s_i) + Σ_{i≥k} log P(machine|s_i) + w·(位置高斯先验)
   训练标签由样本自身 boundary 直接生成，一篇文章产出 ~30 个句子样本，数据量放大 30 倍。

3. 关键教训：**解码器/标定的收益远小于探针判别力，且与探针锐度成反比**。
   在 sharp 探针（TF-IDF + LogReg C=8）上，以下八项全部落在噪声内（93.1~93.35）：
   温度 T、先验权重 w、T×w 网格、线性偏早惩罚、EPS 并列取早、邻域平滑、常数偏移、跨 C 集成。
   同样的 EPS 并列取早在 flat 探针（bge 句向量）上却值 +1.2。原因：EPS 靠「近似并列集里存在更早的正确候选」，后验越尖锐并列集越只含正确答案，放宽只会引入错误候选。
   → 判断某个解码器 trick 是否值得试，先看自己探针的后验锐度；探针越强，解码器上剩的钱越少。

4. 字符级 TF-IDF（char_wb 3-5gram）+ word 1-2gram 的组合，在「人写 vs LLM 续写」这类文风判别上显著强于 bge-base 句向量（93.3 vs 87.8），且 CPU 17 秒跑完全流程。不要默认神经嵌入更强。

5. 误差诊断先做符号统计：本题 ~81% 的错误是「预测偏晚」（探针把机器续写的头一两句判成 human），且这个偏置跨特征族一致。但知道偏置 ≠ 能修——所有基于它的解码器修正都在 sharp 探针上失效。
